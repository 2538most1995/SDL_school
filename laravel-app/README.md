# Sena Care School Laravel

ส่วน **จัดการระบบ → เมนูนักศึกษา → เพิ่มลิงก์** รองรับปุ่มที่ลิงก์ไปหน้าภายในระบบสำหรับนักศึกษา หรือ URL เว็บไซต์ภายนอกแบบ HTTP/HTTPS ซึ่งเปิดในแท็บใหม่ ลิงก์ที่เพิ่มแก้ชื่อ คำอธิบาย ลำดับ เปิด–ซ่อน และลบได้ แล้วกด **บันทึกเมนูนักศึกษา** ไม่ต้องเพิ่ม migration หากมี `districts.student_menu_preferences` แล้ว หน้า **ผลการเรียนของฉัน** ของนักศึกษาแสดงข้อมูลในตารางโดยไม่มีคอลัมน์เปิดรายละเอียด ส่วนหน้าของครู/ผู้ดูแลใช้งานตามเดิม หลัง deploy ใช้ไฟล์ build ใน Git และรัน `php artisan optimize:clear`.

การปรับวันที่ 15 ตุลาคม 2569: หน้ารายงานที่เลือกดูรายวิชา/รายคนจะเริ่มต้นที่ **ดูเป็นรายคน** และมีหน้า **จัดการระบบ → เมนูนักศึกษา** ให้ admin/super admin เปิด–ซ่อน เรียงลำดับ แก้ชื่อและคำอธิบายปุ่มในส่วน **เมนูการใช้งาน** บนหน้าแรกนักศึกษา แยกตามอำเภอ หลัง deploy ให้รัน `php artisan migrate --force` เพื่อเพิ่ม JSON `districts.student_menu_preferences` แล้วรัน `php artisan optimize:clear` และ `npm run build` (หรือใช้ไฟล์ build ที่แนบใน Git) ก่อน migration หน้าแรกยังแสดงเมนูเริ่มต้นได้ แต่ยังบันทึกการจัดเมนูไม่ได้ การซ่อนปุ่มไม่เปลี่ยนสิทธิ์เข้าใช้งานฟีเจอร์

ระบบใช้ Laravel 13 + React 19 + TypeScript และเก็บข้อมูลทั้งหมดในฐานข้อมูลของ deployment นี้ผ่านค่า `DB_*` เท่านั้น ไม่มีการเรียก API หรือเปิด connection ไปยังเว็บไซต์/ฐานข้อมูล Sena Care School เดิม

## แหล่งข้อมูล

- ครู/ผู้ดูแลล็อกอินและจัดการบัญชีผ่านตาราง `users` ภายในระบบ
- นักศึกษาล็อกอินด้วยเลขบัตรประชาชน 13 หลักเพียงอย่างเดียว โดยตรวจว่าตรงกับนักศึกษาปัจจุบันเพียงหนึ่งรายการใน dynamic tables ของ ZIP/DBF ภายในฐาน `DB_*` เดียวกัน แล้วสร้างบัญชี session ภายในโดยไม่บันทึกเลขบัตรซ้ำใน `users`; รหัสนักศึกษายังคงใช้เชื่อมข้อมูลการเรียนภายในระบบ
- อำเภอ สิทธิ์ โปรไฟล์ theme branding audit และ queue อยู่ในฐานเดียวกัน
- งาน สื่อ แผนการสอน ปฏิทิน ตารางสอน และคะแนนใช้ตาราง `learning_*` ภายในระบบ
- นักศึกษา ผลการเรียน วิชา กพช. และคุณธรรมมาจาก ZIP/DBF ที่ผู้ดูแลนำเข้าผ่านระบบ แล้วสร้าง dynamic tables ในฐาน `DB_*`
- ชื่อจังหวัด อำเภอ และตำบลอ่านจาก `resources/data/thai_administrative_areas.csv` ที่ติดมากับ deployment
- หน้า React เรียกเฉพาะ `/api/v1/*` ของ Laravel แอปเดียวกัน และ Laravel HTTP client ปิดกั้น outbound request ที่ไม่ได้อนุมัติ

ชื่อ class/namespace บางส่วนยังมีคำว่า `Legacy` เพื่อรองรับรูปแบบไฟล์ DBF เดิม แต่ไม่มี database connection ชื่อ `legacy` หรือ `legacy_write`

## ติดตั้ง

ห้ามตั้ง `DB_*` ไปยังฐานข้อมูลเดิม และห้ามใช้ `migrate --seed` กับฐาน production เพราะ seeder เป็นข้อมูล demo

```bash
composer install --no-dev --optimize-autoloader
npm install
cp .env.example .env
php artisan key:generate
php artisan migrate --force
npm run build
```

สร้างบัญชีผู้ดูแลแรก:

```bash
php artisan system:create-admin \
  --username=system.admin \
  --name="ผู้ดูแล ระบบ" \
  --district-code=sena \
  --district-name="อำเภอเสนา"
```

คำสั่งจะถามรหัสผ่านแบบซ่อนค่า หากต้องการผู้ดูแลทุกอำเภอให้ใช้ `--super-admin` และไม่ต้องระบุอำเภอ

สำหรับ Plesk Scheduled Task ซึ่งรับคำถามแบบโต้ตอบไม่ได้ ให้ส่ง `--no-interaction` โดยไม่ต้องส่งรหัสผ่าน ระบบจะสร้างรหัสผ่านชั่วคราวและแสดงใน output ครั้งเดียว:

```bash
php artisan system:create-admin \
  --username=system.admin \
  --name="ผู้ดูแล ระบบ" \
  --super-admin \
  --no-interaction
```

งาน `migrate` และ `system:create-admin` เป็นงานครั้งเดียว ให้ปิดหรือลบ Scheduled Task หลังทำสำเร็จ

การอัปเดตลงทะเบียนเรียนรอบวันที่ 2 ตุลาคม 2569 เพิ่มการตรวจเพดานหน่วยกิตฝั่งหน้าเว็บและ API: ประถมศึกษา 14 หน่วยกิต หรือ 17 ในภาคเรียนสุดท้าย, มัธยมศึกษาตอนต้น 17/20 และมัธยมศึกษาตอนปลาย 23/26 รายชื่อแสดง `**` เมื่อหน่วยกิตที่ผ่านแล้วครบทั้งวิชาบังคับและวิชาเลือก; แสดง `*` เมื่อนักศึกษาสามารถลงทะเบียนวิชาใหม่และผ่านจนหน่วยกิตครบภายในเพดานภาคเรียนสุดท้าย แม้ยังไม่บันทึกวิชาใหม่ และไม่อนุญาตให้บันทึกเมื่อเกินเพดาน วิชาเทียบโอนไม่นับเป็นภาระหน่วยกิตของภาคเรียนนั้น หน้าผลการเรียนแสดง GPA แยกตามภาคเรียนและ GPAX สะสม ผู้ดูแล/ครูเลือกดู GPA แต่ละภาคเรียนในรายละเอียดนักศึกษาได้ เมนู **คะแนน** อ่านคะแนนย่อย 1–9, กลางภาค, ปลายภาค, รวม และเกรดจาก `GRADE.DBF` โดยตรง พร้อมแบ่งหน้าสำหรับชุดข้อมูลขนาดใหญ่ สิทธิ์ยังจำกัดตาม district/กลุ่มเดิม การอัปเดตนี้ไม่เปลี่ยน schema; หลัง deploy ให้รัน `php artisan optimize:clear` และ `npm run build`

หน้ารายงานผู้จบหลักสูตรเปิดดูรายวิชาและผลการเรียนย้อนหลังได้แม้ผู้จบไม่อยู่ใน roster ภาคเรียนปัจจุบัน โดยใช้รหัสนักศึกษาคู่กับระดับการศึกษาและคงสิทธิ์ district/กลุ่มเดิม เมนู **คะแนน** เพิ่มปุ่ม **เช็คการคำนวณจาก ITW** เพื่อตรวจผลรวมคะแนนย่อย คะแนนกลางภาค/ปลายภาค/รวม และเกรดตัวเลขแบบ read-only พร้อมแสดงเฉพาะรายการที่ควรกลับไปตรวจใน ITW ระบบไม่แก้ข้อมูลนำเข้า ตัวกรองคะแนนจะคงค่าที่เลือกไว้เมื่อปรับเงื่อนไขอื่น และมีปุ่ม **ล้างตัวกรอง** สำหรับกลับไปดูทุกภาคเรียน/ทุกระดับ/ทุกกลุ่ม/ทุกรายวิชา การอัปเดตนี้ไม่เปลี่ยน schema; หลัง deploy ให้รัน `php artisan optimize:clear` และ `npm run build`

เมนู **ผู้ใช้งาน** อนุญาตให้ `admin` และ `super_admin` ลบได้เฉพาะบัญชีบทบาทครูในอำเภอที่กำลังจัดการ พร้อมยกเลิก session/token และบันทึก audit โดยไม่ลบผลงานการเรียนเดิม ส่วนข้อมูล **N-NET** อนุญาตให้เพิ่ม นำเข้า และแก้ไขเท่านั้น ไม่มี API สำหรับลบรายรายการหรือล้างข้อมูลทั้งชุด การอัปเดตนี้ไม่เปลี่ยน schema; หลัง deploy ให้รัน `php artisan optimize:clear` และ `npm run build`

การตรวจทานลงทะเบียนเรียนเพิ่มเติมแสดงรายวิชาเลือกที่ผ่านและเทียบโอนทุกภาคเรียนไว้ด้านล่างของรายการเลือกลงทะเบียนและแยกจากภาระหน่วยกิตเทอมนี้ ยอดที่เลือกลงทะเบียนอัปเดตทันทีเมื่อเลือก/ยกเลิกวิชา โดยสรุปวิชาบังคับ วิชาเลือก และยอดรวมจากรหัสวิชาที่สมบูรณ์แบบไม่ซ้ำ แถบสรุป ปุ่มพิมพ์ และปุ่มบันทึกจะติดอยู่ด้านล่างของหน้าจอระหว่างเลื่อน พร้อมเว้นพื้นที่ท้ายหน้าไม่ให้ทับข้อมูล ยอดหน่วยกิตที่ใช้ตรวจจบรวมจากรหัสวิชาที่ผ่านจริงแบบไม่ซ้ำ หากยอดรวมระเบียน ITW ต่างกันจะแสดงให้เทียบกัน `*` ประเมินได้ตั้งแต่ก่อนบันทึกการลงทะเบียนใหม่ โดยหาชุดวิชาบังคับที่ยังขาดและสำรองหน่วยกิตวิชาเลือกภายในเพดานภาคเรียนสุดท้าย ผู้ดูแล/ครูกรองรายชื่อเฉพาะผู้มีโอกาสจบได้; ผลประเมินเป็นโอกาสด้านหน่วยกิตและต้องตรวจวิชาที่เปิดสอนก่อนลงทะเบียนจริง

ตัวกรองในหน้ารายชื่อนักศึกษา รายงาน ลงทะเบียนเรียน คะแนน N-NET สถิติลงทะเบียน ผู้ใช้งาน และห้องสอบ คงเงื่อนไขอิสระเดิมเมื่อเปลี่ยนตัวกรองอื่น พร้อมคงชื่อรายการที่เลือกไว้ระหว่างโหลดตัวเลือกใหม่และมีปุ่ม **ล้างตัวกรอง** ในหน้าที่มีหลายเงื่อนไข หน้าที่บันทึกข้อมูลตามชุดภาคเรียน/รายวิชา เช่น สมุดคะแนนและเช็คชื่อเข้าสอบ ยังคงล้างตัวเลือกที่ขึ้นต่อกันเมื่อเปลี่ยนชุดข้อมูลเพื่อป้องกันการบันทึกผิดรายการ การอัปเดตนี้ไม่เปลี่ยน schema; หลัง deploy ให้รัน `npm run build`

เมนู **คะแนนจากข้อมูลนำเข้า** แสดงคะแนนกลางภาคที่ต่ำกว่า 40 เป็นตัวแดง รวมคะแนน 0 จริง โดยคะแนน 40 ขึ้นไปและช่องว่าง/NULL ใช้สีเดิม รองรับธีมสว่าง/มืดและข้อความแจ้งสำหรับโปรแกรมอ่านหน้าจอ การเปลี่ยนนี้ไม่แก้คะแนน เกรด ข้อมูล ITW หรือค่าที่ส่งออก Excel ไม่ต้องนำเข้าใหม่หรือรัน migration; หลัง deploy ให้รัน `npm run build`

เมนู **คะแนนจากข้อมูลนำเข้า** เพิ่มปุ่มและตัวกรอง **ตรวจคะแนนกลางภาค < 40** สำหรับตรวจสอบคะแนนกลางภาค (คะแนนเก็บ) ที่ต่ำกว่า 40 คะแนนโดยเฉพาะ (รวมคะแนน 0 จริง) พร้อมแสดงแถบแจ้งเตือนสรุปจำนวนรายการที่พบ รองรับการกรองร่วมกับตัวกรองภาคเรียน/ระดับ/กลุ่ม/รายวิชา/ค้นหา และส่งออก Excel ได้ตามรายการที่กรอง โดยไม่เปลี่ยน schema; หลัง deploy ให้รัน `npm run build`

การอัปเดตข่าวประชาสัมพันธ์รอบวันที่ 27 กันยายน 2569 เพิ่มตาราง `public_relations_posts` และเมนู **จัดการระบบ → ข่าวประชาสัมพันธ์** สำหรับ `admin`/`super_admin` หลัง deploy ให้รัน `php artisan migrate --force`, `php artisan optimize:clear` และ `npm run build` ผู้ดูแลจึงอัปโหลดรูป เขียนคำอธิบาย และเผยแพร่ข่าวภายในอำเภอได้ นักศึกษาจะเห็นข่าวล่าสุดบนหน้าแรกและเปิดรายการทั้งหมดจากเมนู **ข่าวประชาสัมพันธ์** รูปถูกเก็บใน private storage และไม่ต้องสร้าง public storage symlink.

การอัปเดตเมนู **สถิติ** รอบวันที่ 21 กันยายน 2569 เพิ่มตาราง `statistics_report_preferences` สำหรับจำรูปแบบแกนตั้ง/แกนนอนแยกตามผู้ใช้ อำเภอ และรายงาน พร้อมปรับรายการรายงาน/ประเภทข้อมูลให้เหลือเฉพาะแหล่งข้อมูลที่รองรับจริง หลัง deploy ให้รัน `php artisan migrate --force`, `php artisan optimize:clear` และ `npm run build`.

การอัปเดตรายงาน **สถิติเกรด 2 ขึ้นไป** รอบวันที่ 29 กันยายน 2569 เพิ่มตัวกรองประเภทวิชาเป็นทุกประเภท วิชาบังคับ และวิชาเลือก ทั้งมุมมองรายวิชาและรายคน พร้อมแยกคอลัมน์จำนวนผู้ลงทะเบียน จำนวนผู้ได้เกรด 2 ขึ้นไป และร้อยละในมุมมองรายวิชา และแสดงเกรดจริงพร้อมสถานะถึงเกณฑ์ในหน้าต่างรายชื่อนักศึกษา โดยไม่เปลี่ยน schema หลัง deploy ให้รัน `npm run build`.

การอัปเดตประกาศนักศึกษารอบวันที่ 15 กันยายน 2569 เพิ่มตาราง `announcements` และเมนู **จัดการระบบ → ประกาศนักศึกษา** สำหรับ `admin` ประจำอำเภอ หลัง deploy ให้รัน `php artisan migrate --force`, `php artisan optimize:clear` และ `npm run build` ผู้ดูแลอำเภอจึงสร้าง แก้ไข และสลับเปิด/ปิดประกาศได้ครั้งละหนึ่งรายการ นักศึกษาของอำเภอจะเห็นป๊อปอัปหลังเข้าสู่ระบบ ส่วนครูและผู้ดูแลจะไม่เห็นป๊อปอัปนี้

การอัปเดตทะเบียนอำเภอและหัวตารางสอบรอบวันที่ 24 สิงหาคม 2569 เพิ่มคอลัมน์ `districts.school_code` แบบ nullable หลัง deploy ให้รัน `php artisan migrate --force`, `php artisan optimize:clear` และ `npm run build` ผู้ดูแลสูงสุดจึงแก้ชื่ออำเภอ/รหัสสถานศึกษาได้ โดยรหัสระบบเดิมไม่เปลี่ยน หัวตารางสอบจะแสดงชื่อครูประจำกลุ่มจาก GROUP.DBF ของชุดนำเข้าปัจจุบันด้วย

การอัปเดตเมนูคะแนนรอบวันที่ 21 สิงหาคม 2569 เพิ่มโครงสร้าง 60:40, 70:30 และ 80:20 แบบ additive หลัง deploy ต้องรัน `php artisan migrate --force` แล้ว `npm run build` ข้อมูลสมุดคะแนนเดิมจะไม่ถูกปรับสัดส่วนหรือเปลี่ยนคะแนนย้อนหลัง

สมุดคะแนนใช้ร่วมกันตามอำเภอ ภาคเรียน รายวิชา ระดับ และกลุ่ม ครูผู้สอนร่วม/ครูผู้รับช่วงที่ได้รับมอบหมายกลุ่มเดียวกันจึงกรอกคะแนนและแก้โครงสร้างได้ แม้สมุดคะแนนถูกสร้างโดยบัญชีครูหรือผู้ดูแลคนอื่น โดย API ยังตรวจ district และกลุ่มจากข้อมูลลงทะเบียนทุกครั้งก่อนเขียน

หน้าโครงสร้างคะแนนรองรับการบันทึกเป็นต้นแบบร่วมภายในอำเภอ โดยเลือกใช้ได้กับทุกรายวิชาหรือเฉพาะบางรหัสวิชา การอัปเดตนี้เพิ่มตาราง `learning_score_templates` หลัง deploy ให้รัน `php artisan migrate --force` และ `php artisan optimize:clear` ก่อนใช้งาน

ต้นแบบที่กำหนดเป็น **ทุกรายวิชา** มีคำสั่ง “ใช้กับทุกรายวิชา” บนหน้าคะแนน ครูเลือกครั้งเดียวเพื่อสร้างสมุดคะแนนของทุกวิชาที่ตนเข้าถึงได้ในภาคเรียนปัจจุบัน ระบบใช้ขอบเขต district/กลุ่มจากข้อมูลลงทะเบียน และข้ามวิชาที่มีสมุดคะแนนอยู่แล้วโดยไม่แก้โครงสร้างหรือคะแนนเดิม

การอัปเดตคลังสื่อรอบวันที่ 12 สิงหาคม 2569 มี migration ที่ปรับ `learning_resources.resource_type` จาก enum เก่าของตารางที่ระบบรับช่วงมาเป็น string ของ schema ปัจจุบันโดยไม่ลบข้อมูล หลัง deploy ต้องรัน `php artisan migrate --force` ก่อนทดสอบบันทึกลิงก์ วิดีโอ หรือไฟล์สื่อ

ตัวสร้าง URL ของ Vite ตรวจ base path จาก request ด้วย จึงยังสร้าง URL ใต้ `/SDL_school/build/assets/*` ได้แม้ cache เคยเก็บ `ASSET_URL` ที่รากโดเมน แต่ production ควรกำหนด `APP_URL` และ `ASSET_URL` ให้มี `/SDL_school` ถูกต้องตามตัวอย่าง

Migration รองรับฐานที่มีตารางเดิมอยู่แล้วแต่ migration ledger ว่าง โดยจะตรวจ table/column ก่อนสร้างและไม่ลบข้อมูลหรือ password hash เดิม

หากตาราง `students` ภายในฐานของระบบมี `id` แบบ `INT` จาก schema เดิม migration จะสร้างและซ่อม `student_id` ให้ใช้ชนิดเดียวกันก่อนเพิ่ม foreign key จึงสามารถรันซ้ำหลัง MySQL ทิ้งตารางที่สร้างค้างไว้ได้ โดยไม่ลบแถวข้อมูลที่อ้างอิงไม่ครบ

ระบบยังมี repair migration สำหรับ production ที่ migration ledger เคยบันทึกสำเร็จไม่ตรงกับ schema จริง โดยจะเติมคอลัมน์ผู้ใช้และตาราง `sessions`, `cache`, `jobs`, `audit_logs` ที่ขาดแบบไม่ลบข้อมูลเดิม หลัง deploy ต้องรัน `php artisan migrate --force` และ `php artisan optimize:clear`

เพื่อรองรับ shared hosting ที่ deploy ด้วย Git แต่ยังไม่ได้รันคำสั่งข้างต้น request แรกของโมดูล learning หลังล็อกอินจะตรวจและเติมเฉพาะตาราง/คอลัมน์ learning และ audit ที่จำเป็นแบบ additive ภายใต้ database lock โดยไม่ลบข้อมูลเดิม หาก database user ไม่มีสิทธิ์ `CREATE`/`ALTER` ระบบจะตอบ HTTP 503 พร้อมแจ้งให้รัน migration แทน กลไกนี้เป็น safety net เท่านั้นและไม่แทนที่การรัน migration ตามขั้นตอน deploy

จากนั้นนำเข้า ZIP/DBF ผ่านเมนู Admin เพื่อให้ข้อมูลนักศึกษาอยู่ในฐานใหม่ของระบบ ไม่ควร copy หรือ query ข้อมูลจากฐานเก่าโดยตรง

## เพิ่มอำเภอและนำเข้าข้อมูลหลายพื้นที่

เข้าสู่ระบบด้วยบัญชี `super_admin` แล้วทำตามลำดับนี้:

1. เปิดเมนู **จัดการระบบ → ทะเบียนอำเภอ** และเพิ่มชื่อกับรหัสอำเภอ เช่น `bang-pa-in`
2. เลือกอำเภอใหม่จากตัวเลือกด้านบนของหน้าระบบ
3. เปิดเมนู **ผู้ใช้งาน** เพื่อสร้างบัญชี `admin` ประจำอำเภอ
4. เปิดเมนู **นำเข้าข้อมูล** แล้วอัปโหลด ZIP/DBF ของอำเภอที่เลือก

ระบบผูก queue, batch, dynamic DBF tables, ประวัตินำเข้า และการลบชุดเก่ากับ `district_id` ที่ middleware ตรวจแล้ว ผู้ดูแลอำเภอเข้าถึงได้เฉพาะพื้นที่ของบัญชี ส่วน `super_admin` ต้องเลือกอำเภอเป้าหมายทุกครั้งก่อนนำเข้า ห้ามรวมไฟล์ของหลายอำเภอไว้ใน ZIP เดียวกัน

การแก้ตัวนำเข้า ITW รอบวันที่ 9 ตุลาคม 2569 รองรับสถานะ `.NULL.` ของ Visual FoxPro จาก `_NullFlags` แล้ว ช่องคะแนนอาจมีตัวเลขเก่าค้างอยู่ในไฟล์แต่ ITW กำกับว่าไม่มีค่า ตัวอ่านจะนำเข้าเป็น NULL และหน้าเว็บแสดง `–` โดยไม่เปลี่ยนคะแนนรวม เกรด หรือคะแนนศูนย์จริง สรุปการนำเข้าใหม่มี `dbf_null_handling = foxpro_bitmap_v1` หลังอัปเดตโค้ดให้รัน `php artisan optimize:clear` แล้วนำเข้า ZIP ต้นฉบับล่าสุดอีกครั้งผ่านเมนูผู้ดูแลของอำเภอนั้น เพื่อแทนที่ชุดที่อ่านด้วยตัวนำเข้าเดิม ไม่ต้องรัน migration สำหรับการแก้ครั้งนี้

หากต้องการตารางสอบแบบเดิม ZIP ต้องมี `SCHEDULE.DBF` ของแต่ละระดับที่ใช้งานและ `FIELD.DBF` สำหรับชื่อสนามสอบ ระบบจะนำไฟล์เหล่านี้เข้าเป็นตาราง `db_import_*_schedule` และ `db_import_*_field` ในฐาน `DB_*` ของระบบเอง ส่วนการจัดห้องสอบอ่านจาก `exam_rooms` ในฐานเดียวกัน เมื่อเริ่มภาคเรียนใหม่และยังไม่มีรายการ หน้า **ห้องสอบ** จะแสดงปุ่ม **ใช้ค่าจากตารางสอบ** ระบบจะสร้างรายการจาก `roomno` ของข้อมูลผลการเรียนปัจจุบัน และใช้ห้องในตารางสอบหรือ `ห้อง 1` เมื่อไม่มีเลขห้อง เพื่อให้ค่าทั้งสองเมนูตรงกันก่อนแก้ไขเพิ่มเติม

## ส่งออก ZIP เพื่อย้ายข้อมูล ITW ทะเบียน และคะแนนไปเครื่องใหม่

1. เข้าระบบด้วยผู้ดูแลอำเภอหรือผู้ดูแลสูงสุด เลือกอำเภอ แล้วเปิด **นำเข้าข้อมูล**
2. หากย้ายไป SDL School กด **สำรอง SDL** เหนือตารางชุดข้อมูลปัจจุบัน ระบบรวม DBF/FPT ที่ปรับคะแนนนำเข้าล่าสุด พร้อมวิชาลงทะเบียน/เทียบโอนและข้อมูลสมุดคะแนนเดิมทุกภาคเรียนเป็นข้อมูลสำรอง
3. บนเครื่องใหม่ อัปเดตโค้ด SDL School ให้รองรับชุดข้อมูลเว็บและรัน migration เดิมให้ครบ สร้าง/เลือกอำเภอปลายทาง แล้วเปิด **นำเข้าข้อมูล** อัปโหลด ZIP และระบุภาคเรียนเดียวกับชุด ITW ต้นทาง ระบบกู้คืนทะเบียนและคะแนนให้อัตโนมัติ พร้อมแสดงจำนวนที่กู้คืน

ทะเบียนและคะแนนจากเว็บอยู่ใน `sdl-transfer/` ภายใน ZIP สำหรับนำกลับเข้า SDL School ส่วนคะแนนที่แก้จากตารางนำเข้าจะเขียนลง GRADE.DBF ของ ZIP ทั้งแบบ SDL และ ITW ค่าคะแนนศูนย์และ NULL ยังคงเดิม ระบบ remap รหัสสมุดคะแนน/ช่องคะแนนและผูกผู้บันทึกกับผู้ดูแลที่นำเข้า หากทะเบียนหรือสมุดคะแนนซ้ำกับขอบเขตที่มีอยู่ปลายทาง ระบบยกเลิกการนำเข้าทั้งชุดโดยไม่ทับข้อมูลเดิม ควรย้ายเข้าพื้นที่ที่ยังไม่มีข้อมูลชุดนั้น

### ส่งกลับไปใช้กับ ITW หรือระบบเก่าที่อ่าน DBF

กด **ส่งออก ZIP (ITW)** ระบบนำทะเบียนและคะแนนเว็บเขียนทับ **GRADE.DBF ภายใน ZIP ที่ส่งออก** และเพิ่ม/ปรับ **SUBJECT.DBF** ตามรายการที่เลือกลงทะเบียนหรือเทียบโอน ไฟล์ต้นฉบับบนเซิร์ฟเวอร์และฐานข้อมูลปัจจุบันไม่ถูกแก้ไข ใช้ `?format=itw` สำหรับ API; หากไม่ระบุ format จะเป็น `sdl` เพื่อคง compatibility เดิม

1. ปิด ITW ทุกเครื่องและสำรองโฟลเดอร์ปลายทางก่อนแทนที่ DBF/FPT/CDX ตามโครงสร้างเดิม
2. **สร้างดัชนีใหม่ (REINDEX) ใน ITW/FoxPro ก่อนใช้งาน** เพราะไฟล์ CDX เดิมถูกเก็บไว้เพื่อรักษานิยามดัชนี แต่ดัชนีต้องคำนวณใหม่หลังปรับ DBF
3. สั่งคำนวณเกรดใน ITW อีกครั้ง ตัวส่งออกไม่คำนวณเกรดเอง และเว้น GRADE ของแถวที่คะแนนเปลี่ยนเพื่อไม่ให้เกรดเดิมค้าง

คะแนนจากตารางนำเข้าที่แก้ล่าสุดเขียนลง MIDTERM1–9, MIDTERM (กลางภาค), FINAL (ปลายภาค) และ TOTAL (รวมเมื่อกลางภาคและปลายภาคมีค่าทั้งคู่) ศูนย์จริงยังเป็นศูนย์ ค่า NULL ใช้ bitmap เดิมเมื่อช่องรองรับ ช่อง FINAL1/FINAL2, สัดส่วนใน SUBJECT และข้อมูล binary/memo อื่นคงเดิม สมุดคะแนนเดิมไม่ถูกนำมาทับคะแนนนำเข้าในการส่งออกตามปกติ API เดิมยังเลือก `scores=scorebooks` ได้สำหรับการกู้ข้อมูลเก่าแบบเจาะจง แต่คะแนนที่แก้ตรงจะมีลำดับเหนือกว่าและการจับคู่ที่ขัดกันจะถูกปฏิเสธ

ตามที่กำหนด ระบบ **ไม่ปัดคะแนน** หากค่าเช่น 17.5 อยู่ในช่อง DBF จำนวนเต็มจะแจ้งรหัสนักศึกษา วิชา ภาคเรียน และช่องที่ต้องแก้ เช่นเดียวกับกรณีข้อมูลยาวเกินช่อง คะแนนเก็บเกิน 9 ช่อง รายการซ้ำ/ซ่อมที่กำกวม หรือข้อมูลกลุ่มไม่ตรง ไม่เขียนทับคะแนนของรายการเทียบโอนหรือเกรดพิเศษ และไม่ลบผลเดิมจากการไม่เลือกวิชาในทะเบียนเว็บโดยอัตโนมัติ

### กรอก/แก้คะแนนจาก ITW โดยตรง

หน้า **คะแนน** ใช้ตารางข้อมูลนำเข้าเพียงหน้าเดียว เอาแท็บสมุดคะแนนในระบบและส่วนสร้างโครงสร้างคะแนนออกแล้ว แต่เก็บตารางสมุดคะแนนเก่าไว้เป็นประวัติและข้อมูลสำรอง ไม่ลบคะแนนจริงทิ้ง

ก่อนเปิดใช้ให้สำรองฐานข้อมูลและรัน migrations `2026_10_15_000034_create_imported_score_edits_table.php` และ `2026_10_15_000035_create_imported_score_completions_table.php` ด้วย `php artisan migrate --force` บนฐานข้อมูลระบบที่ต้องการ และเปิด `SYSTEM_STUDENT_DATA_ENABLED=true` กับ `SYSTEM_WRITES_ENABLED=true` หาก migration ยังไม่ครบจะดูตารางได้ แต่บันทึกไม่ได้ (503) การพัฒนารอบนี้ไม่ได้รัน migration กับข้อมูลจริง

ครูแก้ได้เฉพาะกลุ่มที่รับผิดชอบ ผู้ดูแลแก้ได้ในอำเภอที่เลือก: กด **แก้ไขคะแนน** ในแถว กรอกคะแนนย่อย 1–9/กลางภาค/ปลายภาค ระบบบันทึกอัตโนมัติ แล้วกด **บันทึกเสร็จ** เมื่อแก้คะแนนย่อย กลางภาคจะรวมช่องที่กรอกให้ และสามารถกรอกกลางภาคเองได้ ช่องว่างคือยังไม่มีคะแนน ค่า 0 เป็นคะแนนศูนย์จริง คะแนนรวมคำนวณอัตโนมัติและต้องไม่เกิน 100 เกรดถูกเว้นให้ ITW คำนวณใหม่ แถวเทียบโอน/เกรดพิเศษไม่เปิดให้เขียนทับ


## Production safety

- Document root ต้องชี้ `public` เท่านั้น
- ใช้ database user ที่จำกัดเฉพาะฐาน `DB_DATABASE` ของระบบ
- เปิด HTTPS และตั้ง `SESSION_SECURE_COOKIE=true`
- สำรองฐานข้อมูลและไฟล์ import ก่อน deploy/migrate
- ทดสอบ migration ในฐาน staging ก่อน production
- รักษา district scope, role middleware, validation ZIP/DBF และ audit log

การอัปเดตหมวดหมู่และเมนูวันที่ 10 ตุลาคม 2569 เพิ่มเมนู **จัดการระบบ → หมวดหมู่และเมนู** สำหรับ `admin`/`super_admin` สามารถเพิ่มหรือแก้ชื่อหมวดหมู่ ย้ายเมนูไปอีกหมวดหมู่ และเลื่อนหมวดหมู่/เมนูขึ้นลงได้ ลบได้เฉพาะหมวดหมู่ที่ไม่มีเมนูอยู่แล้ว Sidebar เปิด/ปิดเมนูย่อยได้และเปิดหมวดหมู่ของหน้าปัจจุบันให้อัตโนมัติ การตั้งค่าแยกตามอำเภอและยังใช้สิทธิ์เดิมของแต่ละเมนู หลัง deploy ให้รัน `php artisan migrate --force`, `php artisan optimize:clear` และ `npm run build` เพื่อเพิ่ม JSON `districts.navigation_preferences` โดยไม่เปลี่ยนข้อมูลนักศึกษาหรือตารางนำเข้า หากยังไม่รัน migration ระบบแสดงเมนูปกติได้แต่จะไม่ให้บันทึกการจัดเมนู

การปรับลงทะเบียนเรียนวันที่ 12 ตุลาคม 2569 เปิดเมนู **ลงทะเบียนเรียน** ให้ผู้เรียนดูรายวิชาของตนเองตามภาคเรียน แสดงวิชาบังคับด้านบนและวิชาเลือกด้านล่าง โดยแบ่งเฉพาะรายการวิชาเลือกเป็น 2 คอลัมน์และเรียงแนวตั้งบนมือถือ ผู้ดูแลเพิ่มวิชาเลือกแล้วกด **บันทึกการลงทะเบียน** ระบบนำรหัส ชื่อ และหน่วยกิตกลับมาให้เลือกซ้ำสำหรับนักศึกษาระดับเดียวกันในอำเภอเดียวกัน โดยอ่านจากรายการลงทะเบียนที่บันทึกไว้ ไม่คัดลอกข้อมูลส่วนตัวหรือช่องเลือกของนักศึกษาคนก่อน ไม่มี migration ใหม่ หลัง deploy ให้รัน `php artisan optimize:clear` และ `npm run build`.

การแก้สถานะลงทะเบียนวันที่ 12 ตุลาคม 2569 ไม่ตีความผลการเรียนว่างหรือ NULL ที่ยังไม่มีการเข้าสอบว่าเป็นเกรด “ข” อีกต่อไป รายวิชาที่เพิ่งลงทะเบียนและยังไม่มีผลของภาคเรียนนั้นจะแสดง **รอผลการเรียน** โดยยังคงแสดงขาดสอบเมื่อข้อมูลต้นทางระบุ “ข” จริง ไม่มี migration และไม่ต้องนำเข้าข้อมูลซ้ำ หลัง deploy ให้รัน `php artisan optimize:clear`.

เมื่อเลือกวิชาเลือกที่เคยบันทึกไว้ ระบบแสดงชื่อ รหัส และหน่วยกิตให้ทันทีโดยไม่ต้องกรอกซ้ำ เลือกลงทะเบียน/เทียบโอนและเพิ่มหมายเหตุได้ หากต้องการเปลี่ยนรายละเอียดให้กด **แก้ไขรายละเอียดวิชา** ส่วนปุ่ม **เพิ่มวิชาเลือก** ใช้กรอกวิชาใหม่ หลังแก้ข้อมูลให้กด **บันทึกการลงทะเบียน** ตามเดิม.

หน้าลงทะเบียนเรียนแสดงวิชาเลือกเป็นตารางติ๊กแบบเดียวกับวิชาบังคับแล้ว วิชาที่เคยบันทึกและวิชาแนะนำรวมอยู่ในตารางเดียว เลือกลงทะเบียน/เทียบโอนและใส่หมายเหตุได้ทันที วิชาแนะนำที่ยังไม่ได้เลือกจะไม่ถูกเพิ่มในใบลงทะเบียนเมื่อบันทึก ส่วนข้อมูลชื่อ รหัส และหน่วยกิตยังไม่ต้องกรอกซ้ำ หลัง deploy ให้รัน `npm run build` ไม่มี migration ใหม่.


## กรอกคะแนนทั้งตารางและบันทึกอัตโนมัติ

ฟังก์ชันนี้ต้องมี migrations `000034_create_imported_score_edits_table` และ `000035_create_imported_score_completions_table` ก่อนเปิดใช้ พร้อมสิทธิ์เขียนข้อมูลตามเดิม ยังไม่ได้รันกับฐานข้อมูลจริงระหว่างพัฒนา

1. เลือกภาคเรียน กลุ่ม หรือรายวิชา แล้วกด **กรอกคะแนน** เพื่อเปิดทุกแถวที่ยังไม่เสร็จในหน้าปัจจุบัน
2. ระบบบันทึกหลังหยุดพิมพ์ครู่หนึ่งหรือออกจากช่อง โดยแสดงสถานะรายคน ช่องว่างคือยังไม่มีคะแนน ค่า 0 คือศูนย์จริง
3. ใช้ Enter / ขึ้น / ลง เปลี่ยนคน, Shift+Enter ย้อนคนก่อนหน้า, Tab / ซ้าย / ขวา เปลี่ยนช่อง เลือกมุมมองทุกช่อง คะแนนย่อย หรือกลางภาค/ปลายภาคเพื่อลดการเลื่อน
4. กด **บันทึกเสร็จ** ระบบรอคะแนนทุกแถวบันทึกครบก่อนปิดการกรอก หากผิดพลาดจะเก็บค่าที่กรอกไว้และไม่ปิด แถวที่ไม่เปลี่ยนคะแนนจะไม่ถูกล้างคะแนนหรือเกรด
5. ระบบจำรายการที่เสร็จไว้หลังรีเฟรช ปุ่มกรอกทั้งตารางจะไม่เปิดแถวเหล่านั้นซ้ำ ต้องกด **แก้ไขคะแนน** ทีละคนเพื่อเปิดแก้และบันทึกอัตโนมัติอีกครั้ง

หากมีหลายหน้า ให้กดเสร็จในหน้าปัจจุบันก่อนเปลี่ยนหน้า (ปรับขนาดหน้าได้ตามตัวเลือกเดิม สูงสุด 1,000 รายการ) หากมีผู้ใช้อื่นเปลี่ยนคะแนน ให้ใช้ปุ่ม **ใช้คะแนนล่าสุด** ของแถวนั้นก่อนแก้ต่อ สถานะเสร็จเป็นของ batch นั้นและเริ่มใหม่เมื่อนำเข้าชุดใหม่ การส่งออกคะแนนลง GRADE.DBF ใน ZIP และขั้นตอนนำไฟล์ไปแทนใน ITW ยังใช้ตามเดิม
