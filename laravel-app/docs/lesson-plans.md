# แผนการสอนแบบชั้นเอกสาร

หน้า **แผนการสอน** แสดงการ์ดปกเอกสาร พร้อมชื่อ ผู้จัดทำจริง รายวิชา ระดับ ภาคเรียน และจำนวนหน้าที่อ่านจาก PDF มีปุ่มเปิดอ่าน รายละเอียด และแก้ไข/ลบตามสิทธิ์ แสดง 4 คอลัมน์บนจอใหญ่และคอลัมน์เดียวบนมือถือ ไม่มีการสร้างยอดอ่านหรือป้ายแนะนำสมมติ แผนเดิมที่มีเฉพาะข้อความยังเปิดรายละเอียดและแก้ไขต่อได้

## เพิ่มแผนและสร้างปก

เลือกขอบเขต **แผนรายวิชา** หรือ **แผนรวมทุกวิชา** ได้ แผนรวมใช้หนึ่งไฟล์/ลิงก์สำหรับทุกวิชาของระดับที่เลือก ไม่ต้องกรอกรหัสวิชา เช่น แยกอัปโหลดแผนรวมประถม 1 รายการ แผนรวม ม.ต้น 1 รายการ และแผนรวม ม.ปลาย 1 รายการ แต่ละรายการยังเลือกภาคเรียนและสร้างปกจากหน้าแรกได้ตามปกติ หน้าชั้นเอกสารมีปุ่มกรอง **ทุกประเภท / แผนรายวิชา / แผนรวมทุกวิชา** ร่วมกับปุ่มระดับ เมื่อเพิ่มจากรายการที่กรองไว้ แบบฟอร์มจะเลือกระดับและประเภทนั้นให้แล้ว

1. กด **เพิ่มแผนการสอน** กรอกชื่อ ภาคเรียน และเลือกระดับด้วยปุ่ม ระบุรหัสวิชาเฉพาะเมื่อเลือกแผนรายวิชา
2. เลือก **แนบลิงก์** หรือ **อัปโหลด PDF**
3. PDF ไม่เกิน 20 MB จะถูกอ่านในเบราว์เซอร์ด้วย PDF.js เพื่อสร้างภาพจากหน้าแรกและนับหน้าจริง แสดงตัวอย่างก่อนบันทึก ปกมีขนาดไม่เกิน 2 MB ไม่เกิน 2000×2000 พิกเซล จำนวนหน้ารับได้ 1–10,000 หน้า ไม่รับ PDF ที่มีรหัสผ่านหรือไฟล์เสีย
4. สำหรับลิงก์ สามารถแนบ PDF สำเนาเพิ่มเพื่อสร้างปกได้ ลิงก์ยังเป็นทางเปิดเอกสารหลัก และมีปุ่ม **อ่าน PDF สำเนาที่แนบ** หากต้องการเปิดสำรองในระบบ
5. กรอกวัตถุประสงค์ กิจกรรม และการวัดผลตามต้องการ แล้วบันทึก ปุ่มบันทึกจะรอสร้างปกเสร็จและไม่รับไฟล์ที่อ่านไม่ได้ สามารถนำไฟล์ที่เลือกออกเพื่อใช้เอกสารเดิมต่อได้

ภาพปกใช้หน้าแรกของ PDF ที่แนบจริง ไม่ใช้บริการสร้างภาพหรือส่ง PDF ไปประมวลผลภายนอก ไฟล์จะถูกอัปโหลดเมื่อกดบันทึกเท่านั้น เปลี่ยนไฟล์จะสร้างปกใหม่ แก้เฉพาะรายละเอียดจะรักษาไฟล์และปกเดิม เปลี่ยนลิงก์หลักจะล้างปก/สำเนาเก่าที่อาจเป็นคนละเอกสาร เว้นแต่แนบ PDF/ปกใหม่มาด้วย

## ลิงก์ที่รองรับ

- รับลิงก์ HTTP/HTTPS ทั่วไป รวม Google Drive, Google Docs/Sheets/Slides, OneDrive ส่วนตัว และ SharePoint/OneDrive for Business ไม่รับ URL ที่มีข้อมูลเข้าสู่ระบบ อักขระควบคุม หรือ scheme ที่สั่งรันโค้ด
- Drive แบบ `file/d/...` และ `open?id=...` ใช้หน้า preview โดยรักษา resource key ส่วนเอกสาร Google ที่เผยแพร่ใช้หน้า preview/publish เดิม
- OneDrive ใช้ลิงก์แชร์เดิม รวม `1drv.ms` ได้ ลิงก์ Embed ที่ผู้ให้บริการสร้างรองรับการเปิดในหน้าอ่าน SharePoint รองรับรูปแบบ embed ที่กำหนดไว้
- การเปิดในหน้าเว็บขึ้นกับสิทธิ์แชร์และนโยบายของผู้ให้บริการ ทุกลิงก์ที่ถูกต้องยังมีปุ่ม **เปิดในแท็บใหม่** ไม่รับประกันว่าทุกเว็บไซต์อนุญาต iframe
- **ไม่สามารถดึงหน้าแรกจากลิงก์ส่วนตัวหรือทุกลิงก์คลาวด์ได้โดยไม่มีสิทธิ์เข้าถึงไฟล์** ระบบไม่เดา URL รูปปกหรือเรียก Graph/Drive API แบบไร้สิทธิ์ ให้แนบ PDF สำเนาเพื่อสร้างปกอัตโนมัติ หากไม่มี PDF จะแสดงปกข้อความแทนโดยไม่สร้างจำนวนหน้าสมมติ
- ระบบไม่ทำ OAuth ไม่เปลี่ยนสิทธิ์แชร์ และ Laravel ไม่ดาวน์โหลด URL ภายนอก จึงไม่เพิ่มช่องทางให้ URL ผู้ใช้เข้าถึงเครือข่ายภายในเซิร์ฟเวอร์

## สิทธิ์และการเก็บไฟล์

ครูจัดการและอ่านแผนของตนเอง ผู้ดูแลอ่าน/จัดการภายในอำเภอที่เลือก ผู้ดูแลสูงสุดต้องเลือกอำเภอก่อน นักศึกษายังไม่มีสิทธิ์เข้าโมดูลแผนการสอนตามขอบเขตเดิม ทั้ง PDF และปกเก็บใน private local storage และเปิดผ่าน endpoint ที่ตรวจสิทธิ์ ไม่ใช้ public storage link

การบันทึกใช้ CSRF/session และ `SYSTEM_WRITES_ENABLED` เดิม บันทึกพร้อมกันจะล็อกแถวก่อนเติมข้อมูลที่ไม่ได้ส่งมาเพื่อรักษาข้อมูลล่าสุด ไฟล์ใหม่จะถูกล้างเมื่อ transaction ล้มเหลว ไฟล์ที่ถูกแทนที่หรือลบจะล้างหลังบันทึกสำเร็จ เฉพาะพาธที่เป็นเจ้าของโดยอำเภอ/แผนนั้น Audit เก็บสถานะมีไฟล์/ปกและจำนวนหน้า ไม่บันทึกเนื้อหา PDF หรือ token ในลิงก์

## ติดตั้งและตรวจสอบ

หลังอัปเดต Git รันภายใน `laravel-app` บนฐาน deployment ที่ถูกต้อง:

```bash
php artisan migrate --force
php artisan optimize:clear
```

ใช้ production build ที่แนบใน Git ได้เลย หาก build เองใช้ Node.js 22.13 ขึ้นไป รัน `npm ci` และ `npm run build` PDF.js worker/ฟอนต์/CMap/WASM ถูกแนบใน build แล้ว และ `.htaccess` ระบุ MIME ของ `.mjs`/`.wasm` รองรับการติดตั้งใต้ `/SDL_school/` โดยไม่เรียก asset ไปยังรากโดเมนผิดตำแหน่ง

Migration `2026_10_29_000038_add_lesson_plan_documents.php` เพิ่มเฉพาะ nullable columns ของแผน ไม่แก้ข้อมูลนักศึกษา วิชาลงทะเบียน หรือข้อมูลนำเข้า รันซ้ำได้โดยไม่เพิ่มคอลัมน์ซ้ำ และ rollback ไม่ลบเอกสารโดยอัตโนมัติ ก่อน migration ยังอ่านแผนข้อความได้ แต่การเขียนจะตอบ 503 พร้อมคำแนะนำให้ migrate

API: GET/POST `/api/v1/learning/lesson-plans`, PATCH/DELETE `/{id}`, GET `/{id}/file` และ `/{id}/cover` ไฟล์ multipart ใช้ `pdf`, `cover_image`, `page_count`, `source_type=link|pdf`, `external_url` พร้อม metadata เดิม ใช้ POST พร้อม `_method=PATCH` สำหรับแก้ไฟล์ในเบราว์เซอร์ได้

รอบแผนรวมเพิ่ม migration `2026_10_29_000039_add_scope_to_lesson_plans.php` และฟิลด์ `plan_scope=subject|all_subjects` โดยแผนรวมต้องมี `level` และ `semester` แต่ไม่ต้องมี `subject` แผนรายวิชายังต้องระบุรายวิชา การเปลี่ยนประเภทไม่ลบ PDF/ปกเดิม GET รองรับตัวกรอง `plan_scope` และ `education_level` ก่อน limit 250 จึงค้นพบแผนรวมเก่าได้แม้มีแผนรายวิชาใหม่จำนวนมาก หากยังไม่รัน migration ยังอ่านแผนเดิมได้ แต่การบันทึกจะตอบ 503 พร้อมคำแนะนำ โดยแผนเดิมไม่ถูกเปลี่ยนเป็นแผนรวมอัตโนมัติ

ผลตรวจรอบแผนรวม: PHP ผ่าน 512 รายการ ข้ามรายการเดิม 1 รายการ; frontend ผ่าน 87 รายการ มี regression อัปโหลดครบสามระดับโดยไม่มีรหัสวิชา รักษาไฟล์เมื่อเปลี่ยนประเภท ตรวจระดับ/ประเภทผิดหรือค่าว่าง สิทธิ์ครู/อำเภอ กรองก่อน limit 251 รายการ และรัน migration ซ้ำ ทดสอบเบราว์เซอร์ข้อมูลจำลองที่ 1440px/390px แล้ว

ทดสอบ PHP ทั้งระบบผ่าน 508 รายการ ข้ามรายการเดิม 1 รายการ; frontend ผ่าน 84 รายการ รวมลิงก์คลาวด์ 7 กรณี มีการตรวจสิทธิ์หลายบทบาท/อำเภอ ไฟล์ผิดประเภท ขนาดไฟล์ source switching การรักษาเอกสารเดิม และ rollback ไฟล์ พร้อมทดสอบเบราว์เซอร์ด้วยข้อมูลจำลองแยกจากฐานจริง ทั้ง 1440px/390px, dark mode, ปก PDF ภาษาไทย และการอ่าน PDF สำเนาของลิงก์ สิทธิ์เปิดไฟล์ในบัญชีคลาวด์จริงและ performance บน MySQL จริงยังไม่ได้ทดสอบ
